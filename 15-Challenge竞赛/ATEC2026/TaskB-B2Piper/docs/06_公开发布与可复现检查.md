# 6. 公开发布与可复现检查

## 6.1 GitHub 与 Hugging Face 的分工

GitHub 保存：

- 中文教程和问题复盘。
- 轻量检查脚本、配置和结果边界。
- 外部方案的原始链接、许可证和迁移说明。
- 能够在没有比赛资产的情况下阅读和审计的代码。

Hugging Face 保存：

- 与教程对应的公开归档清单。
- 小型脱敏样例和可再分发配置。
- 后续得到授权后再补充的大文件入口。

官方仿真资产、原始视频、checkpoint 和私有日志不因为“放在 HF”就自动获得再分发许可。上传前必须确认来源、许可证和文件体积。

## 6.2 发布前清单

- [ ] 没有 token、密码、SSH 私钥或带认证的 URL。
- [ ] 没有机器用户目录、挂载盘、内网地址和私有 runner 路径。
- [ ] 没有官方资产、私有日志和未授权权重。
- [ ] 没有把环境相机、真值对象位姿或对象 ID 写入正式 observation。
- [ ] 所有实验结果都标注了证据类型和限制。
- [ ] 外部代码有仓库链接、作者归因和许可证说明。
- [ ] 大文件没有绕过 Git LFS 或直接进入普通 Git blob。
- [ ] 文档命令中的路径使用 `$ATEC_ROOT`、`$HF_REPO` 等变量。
- [ ] 评测描述包含 runner、seed、环境版本和官方评测器信息。

## 6.3 复现报告最小字段

一次可复现实验至少要记录：

```text
commit
environment_version
runner
seed
robot_platform
observation_keys
action_space
policy_checkpoint
episode_count
official_score
physical_grasp_verified
placement_verified
video_paths
failure_code
```

缺少 `physical_grasp_verified` 或 `placement_verified` 时，报告只能写“接近/触碰/局部控制结果”，不能写“完整垃圾收集成功”。

## 6.4 对教程读者的建议

先复现官方最小环境，再逐步开启搜索、末端锁定、抓取和放置。每次只替换一个模块；把失败样例和修复方法一起提交，教程的价值往往就在这些边界条件中。
